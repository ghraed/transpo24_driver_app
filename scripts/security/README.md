# SDK 56 security backports

5 November 2026. Both mobile apps use the same reviewed manifest and scripts. No forced major override, version spoofing, advisory suppression, or audit allowlist was added.

`npm ci` runs `postinstall` -> `apply-backports.cjs`. The applicator discovers matching package locations from the npm lockfile and verifies exact before/after SHA-256 bytes. Unknown source, changed versions, missing targets or changed anchors fail closed and require review. Already-patched files are accepted idempotently. `npm run security:backports` checks CJS and ESM Zod3 paths and runs malformed-image probes in a subprocess with a three-second timeout.

- image-size 1.2.1: require a complete box header and finite box size >=8 within input bounds. This prevents the zero-size `jxlp` loop as well as invalid HEIF traversal; reject ICNS entry lengths below eight bytes and incomplete/oversized entries/file lengths before advancing. Retains the 1.x callable API Metro uses. Valid PNG/ICNS and malformed ICNS/JXL/HEIF checks pass. This is a local compatible backport, not an upstream 1.x security release.
- Zod 3.25.76: reject already-invalid oversized max/exact-length arrays and max-size sets before element parsing, in sync and async CJS/ESM. Valid constrained collections and ordinary objects still parse. Follows the upstream size-precheck approach. **Partial mitigation only:** unconstrained collections and the bundled v4 compatibility entry point are not covered. The high advisory remains OPEN, as does the inherited Expo CLI finding.

Source references: [image-size box/ICNS advisories](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq), [ICNS advisory](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr), [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [upstream Zod precheck commit](https://github.com/colinhacks/zod/commit/a0ebf97). Read the SDK [56 versioned reference](https://docs.expo.dev/versions/v56.0.0/) before modifying Expo integration.

npm audit continues to report original versions. On 5 November it reports 3 high, 13 moderate and 1 low in each mobile production dependency graph. The lower moderate count than November 4 comes from refreshed advisory metadata (including the minimatch affected range), not dependency changes in this continuation. Remaining glob/minimatch/deepmerge and inherited paths are unresolved; API retains 4 moderate findings via google-gax/rimraf/glob/minimatch. Registry queries found no fixed same-major image-size1, Zod3, google-gax5, glob10/13 or minimatch9/10 release that closes the recorded advisories. Do not force newer major APIs into these consumers.

Until upstream fixes or fuller tested backports are available: build only trusted repository assets/patterns/configuration, keep CLI/Metro/MCP loopback and unavailable to untrusted clients, isolate build/translation jobs from production data and restrict build filesystem/network permissions. Application source does not import these Node parser/glob APIs; this reachability assessment does not close DEP-01. Do not accept untrusted schema input through Expo tooling. Audit status and the remaining release gate must remain visible.
